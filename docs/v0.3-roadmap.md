# dsh-prime-agent v0.3：Prime Persistent TypeScript Realm

## 状态

v0.3 已按本方案实现：`src/realm/` 承载身份、持久 Worker 与 hybrid runtime，`src/runtime.ts` 是 host row 入口，`agent-presets/prime/` 与 `cordis.patch.yml` 承载安装面。本文保留为契约与验收基准。

v0.3 只修改 `dsh-prime-agent` 插件仓库。`deepseek-harness` 继续作为只读参考，不维护宿主分叉。插件随包提供完整 Prime preset 与 bundle patch：`dsh plugin add` 之后 Prime 出现在 preset 选择器中，无需手动复制或编辑任何组合文件。默认 preset 不变，普通 preset 保持官方 one-shot 语义。

## 产品目标

模型继续只看到 DSH 原生 `run_code`。选择 Prime preset 的 Session 使用长期 TypeScript Worker Realm，使普通顶层变量、函数、对象、Map 和索引在后续 `run_code` cell 中自然可用；其他 preset 仍使用官方 one-shot Worker 语义。

```text
DSH run_code
  → DSH 原生 Code Mode bridge
      → 当前 Agent 的 scoped tools bindings
      → PrimeCodeRuntime
          → 没有 Prime handshake：官方 one-shot Worker
          → 有已认证 Prime handshake：Persistent Realm Worker
```

插件不复制 Code Mode bridge，因此以下能力继续由 DSH 拥有：

- `run_code` schema、SDK 和唯一模型可见控制面；
- 当前 Agent 的工具可见性、schema、权限和 scope；
- nested tool 调度、耐久日志和并发规则；
- abort 传播、结果渲染和输出契约；
- Subagent、Jobs、Goal 与 Workflow 生命周期。

插件只新增 DSH 当前没有的部分：Realm 身份签发、长期 Worker、live namespace、当前 run binding lease，以及 Realm 资源治理。

## 三层数据

| 状态层 | 责任 | 保证 |
| --- | --- | --- |
| Persistent Realm live namespace | 普通顶层变量、函数、对象、Map、索引等活计算数据 | 同一 Worker 内的 cell 间保留；hard kill 后丢失 |
| 持久任务文件 | 大型输入、重要结果与跨重启检查点 | 由文件系统承载，进程重启后仍可恢复 |
| `prime_refine` | 稳定路由与行为经验 | 证据化、乐观并发、事务历史和安全回滚 |

需要跨进程可靠恢复的重要结果必须写入持久任务文件。live namespace 中的值不等于可序列化或可恢复。

## 关键发现：通过 scoped binding 完成 Realm handshake

公开 `CodeRunRequest` 没有 Agent 或 Session：

```ts
interface CodeRunRequest {
  program: string
  bindings: CodeBindingNamespace[]
  signal?: AbortSignal
}
```

但 DSH Code Mode 会根据原始 `exec.agent` 构造当前 run 的 scoped `tools` bindings。Prime 插件因此注册固定名称的 `prime_realm_identity` bootstrap binding；它使用 owning Agent 与插件的 `stateDirectory`，身份协议是固定名称的独立 binding。

Runtime 以 32 字节 CSPRNG challenge 调用：

```ts
await tools.prime_realm_identity({
  protocol: 1,
  challenge: '<base64url-encoded-32-bytes>',
})
```

`PrimeCodeRuntime.run()` 在执行模型程序前检查该固定 binding：

1. 不存在：请求不属于 Prime preset，原样委托官方 one-shot Worker Runtime。
2. 存在：调用 binding；它从自己的 `exec.agent` 取得 Session id并签发带 session binding 和 challenge proof 的不透明 token。
3. Runtime 验证 token 与 proof；成功后只使用 token 中的随机 Realm id 路由 Worker。
4. binding 存在但握手失败时明确失败，不能静默切到 one-shot，避免同一 Session 在两种执行语义间漂移。

该 binding 会出现在 Code Mode SDK 中，但它不是权限凭据：模型只能为自己的 owning Session 取得 token，Runtime 不接受模型把 token 作为路由输入。token 仍按敏感运行元数据处理，不进入默认 renderer、prompt 或 catalog；tool renderer 对该操作只输出固定的 `Prime realm handshake completed`。模型主动调用并返回自己的 token 不扩大权限，但属于不受支持的诊断用法。

这是一项插件私有协议，不改变 `CodeRunRequest`，也不声称 DSH 的通用 CodeRuntime 契约已经包含 Session identity。

## 身份认证与持久分配

### 存储布局

```text
<stateDirectory>/
  realm-identity/
    hmac.key
    sessions/<keyed-session-path>.json
  continual/
```

- `hmac.key` 使用 32 字节随机密钥，文件权限尽可能设为 owner-only。
- Session 文件路径使用带域分隔的 HMAC，不把原始 Session id 暴露到文件名。
- Session 记录只保存 schema version 和随机 Realm id，不进入 prompt。
- 密钥和 Session 记录使用 `withFileLock` 与 `writeFileAtomic` 初始化；已存在但损坏时明确失败，绝不静默重置身份。

### Token 与 challenge proof

协议使用固定字段、固定长度和 length-prefixed binary framing，不使用歧义字符串拼接：

```text
token = base64url(version:u8 || realm:32B || sessionBinding:32B || tokenMac:32B)
proof = base64url(HMAC-SHA-256(K, frame("proof/v1", tokenBytes, challengeBytes)))
```

其中 `sessionBinding` 和 `tokenMac` 分别使用独立 domain 的 HMAC；challenge 必须严格解码为 32 字节。所有输入设固定长度上限，Runtime 使用恒定时间比较验证 MAC 与 proof。challenge 防止工具流水线把其他 run 的合法响应重放给当前请求；Runtime 不接受裸 Session hash，也不接触原始 Session id。

Agent-scoped 工具和 host Runtime 必须配置完全相同的绝对 `stateDirectory`，并各自通过 `RealmIdentityStore` 读取同一 `hmac.key`；不使用进程 singleton。密钥不一致会使握手 fail closed。两处配置都由本包出货——bundle patch 中的 runtime row 与随包 preset 中的工具 row 使用同一 `!!js dshHomePath(...)` 表达式——组合测试必须验证两份出货文件的该值一致。

### Resume 与 fork

- 同一 Session id 正常 resume：读取相同记录，得到同一 Realm id。
- fork：新 Session id 必须签发新 Realm id，不继承父 Realm heap。
- clear/compact 不自动旋转 Realm；其语义仅影响对话上下文。
- v0.3 不提供在线 Realm reset；安全 reset 需要工具侧身份旋转、Runtime pool 通知与 active/queued run 原子栅栏，顺延到后续版本。

## Host Runtime 组合

`PrimeCodeRuntime` 是 host plane 的唯一公开 `ctx.codeRuntime` provider。它在私有 Cordis service realm 中挂载官方 `WorkerThreadCodeRuntime`：

```text
host ctx.codeRuntime = PrimeCodeRuntime
  ├─ Prime handshake 成功 → PersistentRealmPool
  └─ 无 Prime binding → private isolated official WorkerThreadCodeRuntime
```

私有 fallback 通过 `ctx.isolate('codeRuntime')` 和官方插件 API 创建，以复用官方配置校验、TypeScript stripping、one-shot Worker、timeout、abort、输出限制和 dispose 行为。插件不能复制官方 one-shot 实现。

Runtime 配置完整嵌入官方 fallback 配置对象，字段与官方 `computeMs`、`maxWallMs`、`maxOutputBytes`、`maxOldGenerationSizeMb` 一一同名透传，不做隐式映射或另设默认值。官方 web bundle 的 `code-runtime` row 使用 schema 默认值，因此插件 row 也默认留空透传官方 schema 默认；组合回归要证明普通 Code preset 的预算未变化。

替换 host row 由随包 bundle patch 完成。DSH patch 语义中 `name` 只是断言而不能改写既有 row 的插件名，因此 patch 将官方 `code-runtime` row 置为 `disabled: true`，并 insert 一个 `prime-code-runtime` row 指向 `dsh-prime-agent/runtime`。同一 patch 还携带第二对独立操作：停用 host `tool-subagent-report`（固定 `wakeup`，每条子代理上报排成单独轮次），insert `dsh-prime-agent/subagent-report`，按父状态逐次选择投递（父忙 → `quiet` 折入当前轮次 next-step，父闲 → `wakeup` 唤起一轮），对齐 Prime 原型的上报调度；`tests/packaging-boundary.spec.ts` 锁定全部四条 patch 的结构。注意两条 patch 相互独立：若部署替换过 `code-runtime` 的 provider（name 断言失配、disable 被跳过），或用户层重新启用官方 row，两个 provider 会同时竞争 root `codeRuntime`，此时 boot 明确失败——Prime runtime 的 `apply` 负责在冲突时给出指名 patch 语境的诊断，而不是留给 cordis 的裸 service 冲突报错。非 Prime 请求仍委托官方 fallback，因此默认工具展示和 one-shot 执行语义不变。

## Persistent Worker 契约

### Live namespace

每个 `run_code` 调用是同一 Worker 中的下一 cell。普通顶层声明直接进入 live namespace，不需要额外状态 API：

```ts
// run 1
const lookup = new Map(records.map(item => [item.id, item]))
const review = async (id: string) => tools.review_item({ item: lookup.get(id) })
lookup.size
```

```ts
// run 2
await review('a')
```

cell 使用严格模式，支持 top-level `await` 和顶层声明重绑定；末尾表达式是 completion，顶层 `return` 由 V8 直接拒绝。第一版不支持 cell 内原生 dynamic `import()`，也不提供 parser、helper 或第二执行器。

普通 program exception 不回滚 exception 前已发生的 heap 修改。abort、timeout、OOM、协议错误和 Runtime dispose 会 hard-kill Worker，整个 live namespace 丢失。

### Stable tools proxy 与 binding lease

Worker 生命周期长于一次 run，因此不能把第一轮真实 host functions 永久闭包到持久函数中。

- 每个 namespace 使用跨 run 稳定的 null-prototype Proxy。
- 每个 run 分配 run id，并安装该轮允许的 binding names。
- bootstrap 调用完成后，程序获得的 `tools` lease 必须过滤 `prime_realm_identity`，模型代码不能借持久函数调用 bootstrap binding。
- 持久函数只捕获稳定 Proxy，不捕获 host function。
- 每次调用都验证当前 active run id、namespace 和 own member。
- run 结束立即撤销 lease；detached task 后续调用工具必须明确失败。
- 下一轮调用持久函数时，Proxy 自动解析该轮新的 bindings。
- 工具被撤权后，旧 wrapper 即使仍在 heap 中也不能调用被撤销工具。

Host 继续调用 `CodeRunRequest.bindings` 中的函数，所以实际 schema、approval、guard、日志、并发和取消仍由 DSH 执行。

### 串行与后台任务

- 同一 Realm 的 run 严格按 admission 顺序串行。
- 不同 Realm 在全局配额内并行。
- 未被 DSH Jobs/Subagent 管理的 timer、Promise 和后台循环不得跨 run 使用工具或修改 live namespace。
- Worker 包装可跟踪的 timer/immediate APIs（含 `node:timers/promises` 与 scheduler），按 run 跟踪并在 settlement 前清理/取消其 handle。这是尽力而为：`AbortSignal.timeout`、`fs.watch`、socket、native addon 等异步源无法穷举。无条件成立的是 lease——晚醒的续体无论被谁唤醒都调不到工具、发不出日志；私有控制端口的 `postMessage` 在加载期被捕获为常量，且每个 run 的终结消息带一次性 nonce，模型代码伪造 call/done 会因 nonce 不符按协议违规 hard-kill。
- 无法机械证明任意第三方异步资源已 quiescent，因此 v0.3 明确不支持 detached async work；伪造控制消息会 hard-kill Realm，而原生管道输出在 worker 侧被接管（`_write`/`_writev`）归属到当前 run 或丢弃，不连坐下一 run 的 heap。
- 长任务进入 DSH Jobs/Subagent；Realm 只保存 handle 或便利索引。
- queued run 在开始前 abort 时只取消自身，不能终止前面的 active run。
- active run abort 或 timeout 会 terminate Worker，并在下一次访问时创建新 Worker。

## 日志与可观察性

Realm handshake 是 Runtime bootstrap 发起的真实 nested tool call，不伪装成模型源码调用。它会进入 DSH durable dispatch log；`prime_realm_identity` 自己的 output renderer 必须只生成固定成功文案，canonical token/proof 不进入 content。`tools/code-dispatch-log` 只能做额外脱敏，不能作为唯一保密边界。身份与握手路径的任何错误内容都不得包含 token、proof、secret、Session id 或宿主路径；程序自身异常与 worker 崩溃诊断（stack、exit 信息）与官方 one-shot 保持一致，可能包含 worker 路径，属既有官方语义。

fresh Worker 的第一次真实 dispatch 返回一次：

```text
[prime-realm] live namespace started empty
```

同一 Realm 明确 hard-kill 后，下一次真实 dispatch 返回一次 `[prime-realm] live namespace restarted; previous bindings were lost`。正常后续 cell 不返回 retained、binding census 或 generation 编号。idle/LRU 回收后重新进入只报告 fresh namespace；不维护跨 Realm 对象的 loss tombstone。

## Realm Pool 与治理

v0.3 最低配置（与官方共享的四个预算字段沿用官方名字）：

- `computeMs`
- `maxWallMs`
- `maxOutputBytes`
- `maxOldGenerationSizeMb`
- `maxActiveRealms`
- `maxIdleMs`
- `maxHostCallsPerRun`
- `maxParallelHostCallsPerRun`

最低行为：

- active Realm 不因 TTL/LRU 被杀。
- 达到 Realm 上限时优先回收 idle LRU；无法安全回收时明确拒绝 admission。
- idle 回收会丢失 live namespace，下一次访问报告 fresh namespace。
- Runtime dispose 先停止 admission，再终止 active/idle Workers。已接纳的 host binding 没有取消接口，可能在外部继续完成；其迟到回复被丢弃，不阻塞 dispose。
- 同一 `stateDirectory` 必须持有单 host process owner lease；第二个进程不能用相同 Realm identity 启动另一套 heap。异常退出后的 lease 回收必须验证 owner 进程已不存在。
- 没有可靠的 awaited per-Agent release seam，因此 v0.3 使用有界 LRU/idle TTL 和 service dispose，不能宣称 Session dispose 后立即回收。

## 安全边界

- Worker Thread isolation 不是权限沙箱；模型代码与 DSH host 处于同一 OS 用户边界。
- Worker 不持有 Agent、Session、Cordis Context、凭据或真实工具 registry。
- Realm token 是不透明路由标识，不是跨 Session 权限凭据；插件不得自动把它写入 prompt、模型结果或普通 catalog，程序 lease 也不暴露 bootstrap binding。
- Runtime 只接受严格格式和认证成功的 handshake；binding 存在但认证失败必须 fail closed。
- handshake 的预先 abort/期间 abort 映射为 `CodeRunFailure.kind = 'abort'`；身份存储损坏、tool denial、格式或认证失败映射为 resolved `exception`；只有调用方违反 CodeRuntime Service Definition 才允许 `run()` reject。
- 所有 binding 参数、binding 结果和 program completion 都必须保持 lossless JSON 约束。
- Worker 控制协议使用启动时 transfer 的私有 `MessagePort`，不在模型可访问的 ambient `parentPort` 上接收 `call/log/done`；Host 严格验证 run/call id 和单次 terminal settlement。
- 模型代码不能取得 runtime 自用 Inspector capability；公开 `process` 入口必须拒绝 `inspector` 与 module capability。

## Prime preset 与安装

安装体验是"提供一个包，选一个 preset"，不要求用户手动复制或编辑任何组合文件。插件出货三样东西：

1. **随包 Prime preset 目录** `agent-presets/prime/`：`preset.yml`（显示名）加 `agent.cordis.yml`。组合内容是上游 shipped `code` preset 的完整副本，加入 scoped `dsh-prime-agent` row（`prime_refine` 与固定 `prime_realm_identity` bootstrap）。DSH 没有 preset inheritance/patch 语义，preset 层只能整份复制；这份副本是上游快照，会随 DSH 漂移，由 [上游同步手册](upstream-sync.zh.md) 在每次同步时与上游 `code` preset 对照并移植变化。
2. **bundle patch** `cordis.patch.yml`：随 `dsh plugin add` 自动进入 profile 的 bundle 层。它只做两件事——把官方 `code-runtime` row 置为 `disabled: true`，insert `prime-code-runtime` row 指向 `dsh-prime-agent/runtime`。不改 `tools` mode、默认 preset 或任何既有 preset。
3. **启动时 preset 落位**：apps/cli 的 `composeProfile` 用 overlay 强制覆盖 `agent-presets` row 的 `roots`（只保留 shipped root），bundle patch 无法为 roster 注入插件自己的 preset root。因此 host 插件在启动时把包内 preset 目录复制到 `$DSH_HOME/.agent-presets/prime`——仅当目标目录不存在时复制，已存在的目录（无论是否被用户编辑过）绝不覆盖。roster 每次 `list()` 实时重扫用户 root，复制即生效。

preset 内的裸包名由 mount 从 host base 解析，`!!js` 方言在 preset 组合中可用；runtime row 与 preset row 的 `stateDirectory` 使用同一表达式，由组合测试锁定一致。

默认 preset（`standard`）保持不变：Prime 只是 preset 选择器中的一个新选项，用户为某个 Session 选中它才进入 Prime 语义；其他 preset 的请求没有 handshake binding，全部走官方 one-shot fallback。

## 验收

### 核心连续性

- 同一 Session 两次 `run_code` 复用普通顶层函数、Map 和对象。
- Session A/B 严格隔离；fork 不继承父 Realm。
- 同一 Realm 并发 run 串行；不同 Realm 可在配额内并行。
- 持久函数在下一轮使用当前 bindings；工具撤权后旧 wrapper 失败。

### 默认模式不回归

- 没有 Prime handshake binding 的请求完整委托官方 one-shot Runtime。
- native preset 不出现 `run_code` 或 Prime 工具。
- 普通 Code preset 不保留上一轮 heap，预算与官方默认一致。
- 安装不改变默认 preset、`tools` mode 或任何既有 preset；bundle patch 只替换 host `code-runtime` provider。
- preset 落位仅在 `$DSH_HOME/.agent-presets/prime` 缺失时复制；已存在目录（含用户编辑过的副本）绝不覆盖。

### 失败和清理

- identity token/proof 篡改、重放、错 Session binding 和损坏存储明确失败。
- queued abort 不影响 active run；active abort/timeout hard-kill 并报告 binding loss。
- worker crash 不拖垮 host；下一轮创建新 Worker。
- idle eviction、Runtime dispose 后没有 orphan Worker。
- handshake 日志不泄露 token、proof、Session id、secret 或路径。
- 同一个 `stateDirectory` 只允许一个活跃 DSH host 进程；第二个 host 必须因进程 owner lease 明确拒绝启动，避免同一 Realm id 出现两个独立 heap。

### 发布

- typecheck、完整测试、build、publint 和 `npm pack` 内容检查通过。
- 实际 Prime preset 两轮连续性和普通 preset one-shot 回归通过。
- 不修改 `deepseek-harness`，不复制 Agent Loop、Code Mode bridge、Subagent/Jobs 或官方 one-shot Worker。

## 明确不属于 v0.3

- Python/IPython/Jupyter backend。
- 任意 function、closure、socket 或 native handle 的跨进程恢复。
- 自动重放历史 `run_code`。
- 未受 DSH 管理的后台 Promise 跨 turn 调用工具。
- Context Capsule 与 Agent Family 高保真适配。
- 自动 refinement proposal/review/apply 闭环。
- 已落位 preset 副本的自动升级：包内新版本不覆盖 `$DSH_HOME/.agent-presets/prime` 中的既有目录，升级靠删除后重启重新落位。
- 改变默认 preset 或把 Prime 语义施加到未选择 Prime preset 的 Session。
