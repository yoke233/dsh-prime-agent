# dsh-prime-agent v0.3 路线：Context Capsule 与 Agent Family

## 目标

v0.3 要补齐 v0.2 与 Prime Agent 高保真体验之间最重要的差距：父 Agent 不只把子任务当作一个等待结果的 Job，而是能够显式分享上下文、恢复 child handle、继续对话、接收后续汇报，并在不复制 DSH 生命周期的前提下管理一个可持续协作的 Agent family。

目标工作流：

```text
父 Agent 选择 workspace 变量
  → 创建不可变 Context Capsule
  → admission-first 启动 child，并显式授予 capsule
  → 父 Agent 立即继续工作或结束当前 turn
  → child 挂载只读 capsule，独立完成任务
  → child 主动向 parent 汇报，或父 Agent 稍后查询
  → parent 可恢复 handle、追问、取消或删除 child
  → 有价值的结果写回 prime_context
```

## 设计原则

1. **DSH 仍是生命周期所有者。** Agent、Subagent、Jobs、Session、消息、取消与 completion delivery 的权威状态不能搬进插件私有 registry。
2. **Capsule 只传上下文，不拥有 child。** `share`/`mount` 不创建 Worker，也不控制 Job。
3. **Admission 与 completion 分离。** spawn 成功表示任务已接收，不表示 child 已给出答案。
4. **显式授权。** child 只能读取 parent 明确分享的 capsule，不能因为亲属关系自动读取整个 parent workspace。
5. **默认只读与 local。** 挂载内容默认不可修改；global 分享默认关闭。
6. **不把完整值注入 prompt。** prompt 只出现 capsule/child 元数据，内容继续按需读取。
7. **不伪造上游 API。** 若 DSH 缺少必要 family-message 或 child-registry seam，应先补 DSH 原生能力或明确保留差距，而不是在插件中偷偷创建第二套协议。

## 工作流一：确认 DSH 原生能力边界

实现前先对当前 DSH 做一次能力盘点，并把结论写入本文件：

- Subagent admission 是否返回稳定 child id、session id 和 Job id。
- child 是否能识别 parent，parent 是否能恢复 direct children。
- 是否已有 parent/child/sibling 定向消息服务。
- completion delivery 能否唤醒 parent 新 turn，而不仅是 `job_output` 拉取。
- list、follow-up、cancel、close、delete 分别由哪个 DSH service 拥有。
- restart/compaction 后哪些 handle 可恢复。
- 哪些能力已能作为 Code Mode SDK tool 暴露，哪些需要 DSH 新增 adapter seam。

该盘点是实现门槛。优先组合 DSH 已有服务；只有缺少模型侧适配时才在本插件增加薄 facade。

## 工作流二：不可变 Context Capsule

### `share`

为 `prime_context` 增加 `share` 操作：

- 输入显式 key 列表，可选择固定某个 manifest revision。
- 对每个 key 固定 kind、version、blob hash、bytes 与 summary。
- 生成不可变 capsule manifest。
- 返回不透明、高熵的 capsule id；不能只使用可猜测的内容 hash 充当授权凭证。
- 创建后不能修改；需要变化时创建新 capsule。
- 分享值仍引用现有不可变 blob，不复制大内容。
- local capsule 默认只能通过显式 id 交给 child；global capsule 仍受部署策略控制。

### `mount`

为 `prime_context` 增加 `mount` 操作：

- child 提交 capsule id，将其挂载到自己的 local workspace。
- 默认使用独立 namespace/prefix，避免覆盖 child 现有 key。
- mount 默认只读；child 的派生结果写入自己的普通 local key。
- 重复 mount 必须幂等。
- key 冲突、失效 capsule、超额配额和缺失 blob 必须明确失败。
- catalog 标记条目来源 capsule，但不泄露 parent Session id 或宿主路径。
- unmount 只移除引用，不删除共享 blob。

### Capsule 状态建议

```ts
interface ContextCapsule {
  schemaVersion: 1
  id: string
  createdAt: number
  sourceScope: 'local' | 'global'
  sourceRevision: number
  entries: Array<{
    key: string
    kind: ContextValueKind
    summary: string
    blobHash: string
    bytes: number
    version: number
  }>
}
```

具体磁盘格式在实现审查时冻结。授权 token、公开 id 与磁盘文件名是否分离，需要经过安全审查后决定。

## 工作流三：Agent family adapter

v0.3 需要在 Code Mode 中形成稳定契约；名称可在能力盘点后确定，但至少覆盖：

| 操作 | 语义 |
| --- | --- |
| `spawn` | admission-first 启动 child，返回稳定 handle，不返回最终答案 |
| `list` | 恢复 direct children 及 running/completed/closed 状态 |
| `send` | 向指定 child 发送 follow-up；child 可显式回复 parent |
| `collect` | 兼容 DSH Job completion 的有界结果读取 |
| `cancel` | 请求取消仍在运行的 child/Job |
| `delete` | 关闭可寻址 child 并移除活动引用，但不伪装成删除耐久 transcript/artifact |

实现方式必须是 DSH 服务上的薄 adapter：

- 不保存第二份权威 child 状态。
- handle 中记录 DSH 权威 id，而不是插件自创运行实例。
- 所有操作重新向 DSH 查询当前状态，不能相信 prompt 中的旧 snapshot。
- 权限、深度限制、provider、工具过滤、取消和日志仍由 DSH 执行。
- 错误必须区分未找到、无权限、已完成、已关闭、已取消和 provider 失败。

如果 DSH 当时只支持 Job 拉取，不支持 family message，v0.3 可以先交付 `spawn/list/collect/cancel/delete + capsule`，但必须把 `send` 与 child 主动 reply 标为未达成，不能宣称完全兼容 Prime。

## 工作流四：Capsule 与 child admission 组合

提供一条标准 Code Mode 配方：

1. `prime_context.catalog` 获取 parent revision。
2. `prime_context.share` 固定 child 所需 key。
3. family `spawn` 显式携带 capsule id 和任务说明。
4. child 启动时获得 capsule id，并调用 `mount`；若 DSH 提供安全的启动钩子，可由 adapter 自动完成。
5. parent 保存 handle 到自己的 workspace，随后继续其他工作。
6. child 将结果写入自己的 workspace，并通过消息或 completion 汇报必要摘要。
7. parent 按需读取结果，不把整个 child transcript 注入 prompt。

需要验证一个 capsule 能安全授予多个 child，以及 child 不能通过 capsule id 枚举其他 capsule。

## 工作流五：Blob 保留与垃圾回收

v0.2 的 delete 会保留 blob。v0.3 引入 capsule 后，需要建立引用生命周期：

- 活跃 local/global manifest 和 capsule manifest 都是 blob 引用根。
- GC 必须与 manifest/capsule writer 协调，不能删除尚未提交或刚被引用的 blob。
- 优先采用 mark → quarantine → grace period → delete，而不是立即物理删除。
- 提供 dry-run/统计能力：reachable、unreferenced、quarantined、bytes。
- 默认自动 GC 是否开启由部署配置决定；第一版可只提供安全的显式 maintenance 命令。
- 不因配额后来收紧而让既有 capsule 无法读取；读取兼容性与新写入准入应分开考虑。

## Prompt 与模型体验

v0.3 的动态 prompt 继续保持有界，只增加：

- 已挂载 capsule 的 id 缩写、namespace、条目数和字节数。
- direct child 的稳定 id/name、状态和最后活动时间等有界 roster。
- 精确说明 admission handle 不是 child answer。
- 精确说明何时等待、何时结束 turn、何时发送 follow-up、何时清理 child。

不得注入完整 capsule 内容、完整 child transcript 或未经限制的 Job output。

## 状态与兼容性决策

pre-v2 状态仍不在支持范围内。v0.3 开发前需要明确 v0.2 状态策略：

- 优先让现有 v0.2 manifest/blob 保持可读，并以附加 capsule 状态扩展。
- 如果必须变更 manifest schema，应提供明确、可测试、原子化的 v0.2 → v0.3 迁移，或者明确将 v0.3 定义为新的破坏性状态根；不能静默用新 parser 破坏现有状态。
- capsule 与 mount schema 在首个发布候选前冻结。

## 测试与验收

### Capsule

- 分享固定的是指定 revision 的 blob，parent 后续更新不会改变旧 capsule。
- child mount 后可跨 turn/restart 恢复并按需读取。
- 未持有 capsule id 的 Agent 不能枚举或挂载 capsule。
- namespace 冲突、配额、损坏和并发 mount 明确失败。
- catalog/prompt 不出现完整值、parent Session id 或宿主路径。

### Agent family

- spawn 在 child 完成前返回 admission handle。
- parent admission 后能继续写 workspace 或结束 turn。
- list 在 restart/compaction 后恢复 direct child。
- follow-up 到达正确 child，child reply 到达正确 parent；若 DSH 缺少该能力则明确记录未达成。
- cancel/delete 作用于正确 DSH 实例，不影响 sibling 或无关 Job。
- completion/output 始终有界并进入 DSH 耐久日志。

### 真实组合

- 使用真实 DSH Code Runtime、Subagent、Jobs 和 Session，而不是只测 fake tool。
- 至少覆盖两个并行 child、一个后台 child、一个 follow-up、一个取消、一个进程重启恢复。
- 验证其他插件注册的工具仍通过 Code Mode SDK 正常调用。
- 运行 typecheck、完整测试、build、publint、bundle dump 和实际 profile 启动探活。

## 明确不属于 v0.3

- 持久 IPython/Python Kernel。
- 复制 Prime Daemon、Worker 或 Agent Loop。
- 自动 refinement proposal/review/apply/outcome 闭环；继续留给 v0.4。
- 默认开放 global context/refinement/capsule。
- 把 child transcript 或整个 workspace 自动塞入模型上下文。
- 用插件私有 registry 取代 DSH Jobs/Subagent/Session。

## 推荐实现顺序

1. DSH family/message/child-registry 能力盘点与设计决策。
2. Capsule schema、授权模型和状态兼容性审查。
3. `share`、`mount`、`unmount` 与只读 namespace。
4. DSH-native family adapter 的 spawn/list/collect/cancel/delete。
5. send/reply/follow-up；必要时先补 DSH 原生 seam。
6. Capsule + child admission 一体化配方和 prompt。
7. Blob 引用统计、quarantine 与 GC。
8. 真实 restart/compaction/并发/权限测试。
9. README、架构、上游差异手册与发布审查。

## 完成定义

只有满足以下条件才能称为 v0.3 完成：

- parent 能显式分享最小上下文给 child，child 无法读取未授权 workspace。
- spawn 是 admission-first，parent 不必等待 child 答案。
- child handle 可以在后续 turn 和进程恢复后重新发现。
- parent 至少可以可靠 collect/cancel/delete；send/reply 若未交付必须明确降级说明。
- capsule 与 child 元数据有界，完整内容仍按需读取。
- 不复制 DSH 生命周期，不扩大工具权限。
- 全部真实组合测试、发布检查和安全 review 通过。
